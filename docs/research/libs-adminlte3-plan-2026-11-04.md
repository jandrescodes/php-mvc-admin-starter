# Librerías externas para la migración a AdminLTE 4 + Bootstrap 5.3: versiones, compatibilidad y descargas

> **Parcialmente superado:** este informe asume el plan conservador (jQuery + DataTables + Select2). La decisión vigente es el stack sin jQuery de `al4-stack-2026-11-04.md`. Sigue valiendo para SweetAlert2, Chart.js, SRI y avisos de seguridad.

Investigación de solo lectura, hecha el 2026-11-04. Las versiones salen de `npm view` (registry.npmjs.org), la API de jsDelivr, Packagist y GitHub, nunca de memoria. Las versiones instaladas se leyeron de las cabeceras de los archivos en `public/`.

Tags SRI: los sha384 los calculé descargando cada archivo de jsDelivr y pasándolo por `openssl dgst -sha384`. Valen para el archivo exacto de esa URL, sea por CDN o copiado tal cual a `public/`.

## 2. ¿Sigue haciendo falta jQuery?

- **AdminLTE 4 y Bootstrap 5.3: no.** Si `window.jQuery` existe y `<body>` no tiene `data-bs-no-jquery`, Bootstrap 5 registra igual los puentes `$(el).modal()`, `.tab()` y `.tooltip()` (`getjQuery()` en `bootstrap.bundle.js` 5.3.8). Por eso los `.modal(`/`.tab(`/`.tooltip(` del inventario siguen funcionando con jQuery cargado antes que `bootstrap.bundle`. Los atributos deben ser `data-bs-*`.
- **Select2 4.1.0: sí** (hard dependency).
- **jQuery Validate 1.22.1: sí** (peer `^1.7…^4.0`).
- **DataTables 3.x: no**, aunque usa jQuery si está presente. Con DT 2.x sí era obligatorio (`jquery >=1.7`).
- **Conclusión:** jQuery se queda (C2) por Select2 y Validate.
    - **4.0.0 es viable**: Select2 4.1.0 y Validate 1.22.x la declaran soportada, y el código propio no usa APIs eliminadas.
    - Condición: smoke test con jQuery Migrate 4.0.2 en dev (sin warnings) sobre login, users create/update (Select2 + validate), modal de roles/permisos y DataTables.
    - Si aparece cualquier fallo, usar 3.7.1, que no requiere ningún cambio.
- **Orden de carga obligatorio:** jQuery antes que `bootstrap.bundle` (para los puentes `.modal()`) y antes que todos los plugins.

## 3. Dark mode: requisito transversal

Todo el CSS de terceros moderno usa **`[data-bs-theme=dark]`**, no la clase `html.dark-mode` del proyecto:

- `dataTables.bootstrap5.min.css` 3.1.5 (8 reglas) y `buttons.bootstrap5.min.css` (2 reglas).
- `adminlte-select2.min.css` (incluye el dropdown que se cuelga del `body`).
- El propio AdminLTE 4.

Si `theme-toggle.js` y el anti-FOUC ponen `data-bs-theme` en `<html>`, esas librerías se oscurecen solas y sobran los parches de `dark-mode.css` para `.dataTables_*`, `.dt-buttons`, `.select2*` y `.swal2-*`. SweetAlert2 necesita además `theme: 'dark'|'light'` (o `bootstrap-5-dark`/`-light`) leído del estado actual. `responsive.bootstrap5.min.css` no trae reglas dark. Chart.js toma los colores por JS (`applyChartTheme()` reescrito con la API v4).
